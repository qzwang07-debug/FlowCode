## Plan and acceptance gates

1. Add versioned execution contracts, complete fixtures, reference validation,
   confirmation invalidation, and non-destructive v1 migration tests.
2. Pin an external OpenCode binary; verify the OpenAPI protocol with a fake server
   and the actual binary, including authentication, restricted test MCP,
   structured output, configuration loading, and shutdown.
3. Probe Windows isolation using synthetic canaries; document each observed
   boundary and deny automatic unreviewed execution unless all required boundaries hold.
4. Resolve the user-selected Ziniao test environment exactly; verify CLI contracts,
   recording transport and Playwright/context/artifact feasibility using local fixtures.
5. Preserve sanitized evidence, capability matrix and ADRs; run regression gates,
   review the diff, and make local commits. No push, PR, or merge in this delivery.

Real OpenCode, fake protocol, OS boundary and browser results are reported separately.
Unknown or failed capabilities are never counted as supported.
