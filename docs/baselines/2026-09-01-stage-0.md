# Regression baseline — Stage 0

This document freezes the pre-change Skill Recorder 0.5.0 behavior used to judge
FlowCode Stage 0. It records results before the product rebrand and does not claim
that existing model-dependent Eval failures were fixed.

## Source and environment

- Recorded: 2026-09-01 (Asia/Shanghai).
- FlowCode HEAD: `f339aec` (`docs: define FlowCode architecture and implementation plan`).
- Upstream baseline: `c7f2fe4402527a0eb7f4fc1b653bf438229bac61` (Skill Recorder 0.5.0).
- OS: Windows 11 Professional 10.0.26200, x64.
- Runtime: Node.js 24.19.0 and npm 11.17.0.
- Model Provider: GitHub Copilot; model `auto`; semantic judge disabled.
- Model scenario count: 24 (9 Describer, 10 Automation Builder, 5 Skill Builder).

The default system Node.js 24.18.0/npm 11.16.0 did not meet the repository engine
range, so all recorded commands used the bundled Node.js 24.19.0 runtime and npm
11.17.0. The initial dependency install reported three high-severity audit
findings. No automatic `npm audit fix` was used; the findings were later classified
and resolved with reviewed, locked patch overrides as recorded below.

was rerun with the same Node.js/npm toolchain:

| `npm run eval:sensitive` | Pass, 21/21 | 7.361 s |

| `npm run eval:skill` | Baseline failure, 4/5 | 88.155 s |

The post-change Describer run scored eight scenarios at 100% and the
`irrelevant-detour` scenario at 92%; all nine passed. The two Builder totals match
the pre-change baseline despite per-scenario text variation. No Builder prompt,
catalogue, scoring rule, or analyzer workflow was changed beyond recognizing the
new FlowCode app name while retaining the legacy name for old recordings.

The first `npm run compliance:licenses` attempt could not fetch the existing
immutable libtiff COPYRIGHT raw URL because GitLab returned HTTP 403 for the old
compliance User-Agent, the new FlowCode User-Agent, and a generic browser
User-Agent. The Stage 0 follow-up added a generic pinned-Git-file fallback. A real
cold-cache run confirmed that the raw URL failed, the same official GitLab
repository and full commit were used automatically, and the result was accepted
only after matching the existing reviewed SHA-256
`fbd6fed7938541d2c809c0826225fc85e551fdbfa8732b10f0c87e0847acafd7`.
`REMOTE-MATERIALS.json` records the fallback repository, revision, repository path,
and retrieval mode. No source URL, reviewed hash, or compliance guard was weakened.

For the desktop smoke test, `npm run electron:install-reviewed` installed and
verified Electron 43.1.1 for Windows x64. `npm start` then reached the Electron main
process, initialized sensitive-model provisioning, and logged the FlowCode capture
state. The process was stopped without recording. Global shortcut registration was
unavailable in the test desktop, which the inherited application handles as a
non-fatal warning.
